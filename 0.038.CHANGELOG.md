# Changelog — aventyrs-core 0.0.38

One addition: a dano bonus can now say **what it is made of**.

## `DamageBonusBreakdown` — the named parts of a `DamageBonus`

`AbstractSkillInteraction` folds every dano-roll contribution into a single `DamageBonus`, so a
consumer reporting an attack could show the total and nothing else — "+4" with no way to tell
whether the base Ataque Corpo-a-Corpo half-Força term was in it at all.

Three new types in `org.aventyrs.core.character`:

- `DamageContributionSource` — one constant per source the sum already scans: `MEIA_FORCA`,
  `SKILL_COMPETENCY_ABILITY`, `EGO_ADVANTAGE`, `FEAT`, `TEMPORARY_BONUS`, `CONDITION`,
  `TARGET_CONDITION` (the victim's Flanqueado), `MANOEUVRE` (an Investida's +2).
- `DamageContribution(source, value)` — never zero-valued; a source that contributed nothing is
  left out entirely.
- `DamageBonusBreakdown(contributions)` — with `total()` and `valueOf(source)`.

`InteractionResult` gains `damageBonusBreakdown`, `null` exactly when `damageBonus` is.

**The invariant:** `breakdown.total() == damageBonus.getValue()`. The two are built together in
`sumDamageBonus` and replaced together in `applyAttackTargetBonuses`, so they cannot drift.

**No behaviour change:** the arithmetic of the sum is untouched; only its provenance is now
reported. Nothing in this core reads the new field — it is for the UI and API layers that report a
dano roll.

**When adding a new dano-bonus source**, add its `DamageContributionSource` constant in the same
change as its scan, or it will be summed into the total while staying invisible in the breakdown.

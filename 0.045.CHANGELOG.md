# Changelog — aventyrs-core 0.0.45

**"2 outras Habilidades de Santo" now counts every Habilidade the Santo holds.** It used to count
only constants of the same Java enum, which read the clause wrongly and made two of Santo's four
Habilidades unreachable in a common case.

## The bug

`AventyrTitleAbility#isEligible` scoped its "outras Habilidades" count by catalog *class* — the
concrete enum the constant being acquired belongs to. For `AbencoadoPelaLuzAbility
#GLORIA_RELAMPEJANTE_DE_TESLA` that is right: its clause names one Especialização, "Requer 2
Habilidades de **'Abençoado pela Luz'**". For `SantoAbility` it is not. Those clauses name the
*Título* — "Requer 1 Especialização e 2 outras Habilidades **de Santo**" — and a Habilidade that a
held Especialização brought is a Habilidade de Santo just as much as one from `SantoAbility`
itself. That is what holding the Especialização means.

So a Santo holding one Especialização and two of its gated Habilidades counted **0** toward that
clause, and `BASTIAO_DOS_NECESSITADOS` and the `GUARDA_VIDAS` Suprema could never be acquired —
they simply never appeared among a Título's acquirable abilities, with nothing to say why.

## The fix

A new `AventyrTitleAbility#getRequiredOtherAbilitiesScope()` returns which Habilidades the count
admits: those gated on the Especialização it names, or — empty — every Habilidade the Título holds.

**It defaults to the constant's own `getRequiredSpecialization()`**, which gets both catalogs right
with nothing declared per constant: a `<Specialization>Ability` is by definition gated on its own
Especialização and its clause names that same one, while a `<Title>Ability` names no Especialização
at all and its clause names the Título. Override only where a constant's text disagrees.

- `isEligible` also **excludes the ability itself** from the count now, rather than relying on it
  not being held yet. "Outras" is the rules text's own word, and nothing stopped a re-grant from
  letting an ability pad its own prerequisite.
- `isSameCatalog`/`catalogOf` are gone, and with them the `getDeclaringClass()` workaround for
  constant-specific class bodies — the scope is now a named Especialização, not a Java class.

## Compatibility

Not a breaking change: the new hook is defaulted, and no signature moved. **Behaviour does change**
— abilities that were silently unacquirable become acquirable. Every existing eligibility test
passed unchanged under the new rule, including the three that pin Glória Relampejante de Tesla's
narrow scope; the new ones cover the wide reading, the mixed case (one of each source counting
toward the same total), and self-exclusion.

# Changelog — aventyrs-core 0.0.34

Written for projects that consume this library. Two themes, and they meet in one place — a hidden
character gives themselves away by moving, and an Investida is a movement:

1. **Esconder-se** (§1–§7) — a Furtividade roll now becomes a real, persistent Grau de Dificuldade
   that other combatants have to roll Atenção against, and that its holder loses by attacking,
   moving or rolling at someone.
2. **Investida** (§8–§11) — the charge becomes a real manoeuvre: priced, gated, with its own
   movement allowance, a bonus to its dano roll and a penalty for missing. Moving now also reports
   **who is entitled to react to it**.

`./gradlew build -x javadoc` passes. 66 new tests — 30 for Esconder-se (`HidingServiceImplTest`,
including one driving the §1 flow end to end through the real `FurtividadeInteraction`) and 36 for
the Investida (`ChargeServiceImplTest`, `MovementReactionServiceImplTest`, `ChargeAttackTest`, the
last of these going end to end through the real `AttackDelivery`).

**No breaking changes.** Three new services, one new `Condition` subclass, two new enums, one new
`CombatantSheet` method, one new optional `SkillRoll` field, three new `Feat` hooks, four new
`AttributeAbility` hooks, one new (defaulted) `MonsterTemplate` column. Every existing constructor,
builder and overload keeps working untouched; the new `SkillRoll` field is the last parameter of a
new longest constructor that every shorter one delegates into.

The only thing that throws is `ChargeService#begin`, on a charge the rules refuse (§8) — four new
`TranslatableMessages` keys go with it. Nothing else here throws: every other method answers a
question or mutates a sheet.

## 1. How to hide

Four steps. This core never rolls, so the dice are always yours; the service is what remembers
what they meant.

```java
HidingService hiding = new HidingServiceImpl();

// 1. Roll Furtividade the ordinary way. Nothing new here.
SceneContext hiderContext = scene.buildContext(hider, distances);
SkillRoll roll = new SkillRoll(List.of(6, 4, 3), FurtividadeSpecialization.MAESTRIA_DA_OCULTACAO);
InteractionResult result = new FurtividadeInteraction().applyTo(hider, hiderContext, roll);
int total = result.getSkillRollBonus() + roll.getTotal();   // e.g. 8 + 13 = 21

// 2. Turn the total into a concealment. The flag says whether the roll named
//    a held MAESTRIA_DA_OCULTACAO — see §3 for why it matters.
Hidden hidden = hiding.hide(hider, total, true);
```

The character now holds `ConditionType.ESCONDIDO`, concealed at Difícil +1 (§3 works that 21
through). It is **open-ended** — it does not tick down with the Rodadas, it ends when something
reveals it — so `finishTurn()` / `startNewRound()` leave it alone.

```java
// 3. Let each enemy look, once. The GD they face depends on their own Especialização.
for (CombatantSheet watcher : scene.getEnemies(hider)) {
    Integer gd = hiding.getConcealmentValue(hider, watcherHasSentidosApurados);
    // ... you roll that watcher's Atenção against gd ...
    hiding.resolveDetection(hider, watcher, attentionTotal, watcherHasSentidosApurados, hiderContext);
}

// 4. Ask, any time afterwards.
if (hiding.isHiddenFrom(hider, someEnemy, hiderContext)) { /* they can't see them */ }
```

And when the hidden character does something that gives them away:

```java
hiding.reveal(hider, RevealTrigger.ATTACK);   // true if it actually ended a concealment
```

## 2. Where the state lives — `sheet.Hidden`

`ConditionType.ESCONDIDO` existed but carried no number, so nothing could be opposed to it. It is
now held as a **`Condition` subclass**, `org.aventyrs.core.sheet.Hidden`:

```java
DifficultyLevel getDifficultyLevel();          // the tier the Furtividade roll reached
int             getBonus();                    // by how much it exceeded that tier
int             getConcealmentValue();         // getBaseValue() + bonus — what an ordinary watcher needs
int             getConcealmentValue(boolean observerIsExpert);
boolean         isDetectedBy(CombatantSheet observer);
Set<UUID>       getDetectedBy();
static Hidden   fromRoll(int furtividadeTotal, boolean rolledAsExpert);
```

Reachable from either side:

```java
Optional<Hidden> held = sheet.getHidden();     // new on CombatantSheet
Integer gd = hiding.getConcealmentValue(hider);   // null when not hidden
```

A subclass rather than a value field on `Condition`, because exactly one condition in the
catalogue has a magnitude — the other sixteen would carry a meaningless number. Same shape
`Regeneration` already takes beside `TemporaryBonus`.

**Detection is per observer and recorded on the concealment.** One Goblin failing its Atenção
does not blind the Elfo beside it, and a watcher who succeeded keeps seeing without re-rolling
every Rodada. That set dies with the concealment: revealing and hiding again builds a fresh
`Hidden`, so whoever had spotted the old hiding place starts over.

## 3. The GD is a tier plus a bonus, and both Especializações are worth one

A concealment is not stored as a bare total. It is a `DifficultyLevel` plus a flat modifier — the
same pair a foe already presents with `getAttackDifficulty()` / `getAttackBonus()`, flattened the
one way this core flattens any GD (`getBaseValue() + bonus`, as `AttackReceiver` and
`SkillRoll#against` do).

That is what lets **Maestria da Ocultação** (hiding) and **Sentidos Apurados** (watching) each buy
what an Especialização buys everywhere else in this ruleset: the easier threshold of the tier in
play. A Furtividade total of **21**:

| Rolled | Stored as | Ordinary watcher needs | Watcher with Sentidos Apurados needs |
|---|---|---|---|
| with Maestria da Ocultação | Difícil +1 (expert threshold 20) | **24** (23 + 1) | **21** (20 + 1) |
| raw | Médio +3 (base threshold 18) | **21** (18 + 3) | **19** (16 + 3) |

So a specialised hider is harder to find than the dice alone say, and a specialised watcher takes
exactly that advantage back. Pass the flags honestly:

- `hide(hider, total, rolledWithSpecialization)` — `true` when the roll named a held
  `MAESTRIA_DA_OCULTACAO`, i.e. the same condition under which `AbstractSkillInteraction`
  thresholded it as an expert roll. The short `hide(hider, total)` is the raw case.
- `getConcealmentValue(hider, observerIsExpert)` / `resolveDetection(..., observerIsExpert, ...)`
  — `true` when *that watcher's* Atenção roll names a held `SENTIDOS_APURADOS`. The shorter
  overloads are the ordinary watcher.

A third form takes the GD outright, for a Narrador setting a hiding place by fiat or a
concealment restored from persisted state:

```java
hiding.hide(hider, DifficultyLevel.VERY_HARD, 2);
```

A total too low to reach even Muito Fácil clamps to that tier with a **negative** bonus, so the GD
still reproduces the roll. Hiding badly is a bad hiding place, not a failure to hide.

## 4. Who has to roll, and who never does

**Your own sub-group always sees you.** `isHiddenFrom` / `resolveDetection` read the *hider's own*
`SceneContext` and treat everyone in `getAllies()` (matched by sheet id) as seeing them plainly —
only characters outside the group ever roll. A `null` context is the one place in this core where
"cannot tell" leans toward the holder: with no snapshot, group membership can't be established and
the concealment stands, because a caller driving the API without a Scene should not silently lose
one, and being hidden from an ally costs that ally nothing this core models.

**A foe never rolls.** `MonsterTemplate` gains a **fifth authored number** beside DF / DM / GD de
ataque / bônus de ataque:

```java
int getPerception();   // default: HidingService.DEFAULT_MONSTER_PERCEPTION (14)
```

`resolveDetection` reads it in place of an Atenção roll, and **ignores** any `attentionTotal` or
`observerIsExpert` passed for a `MonsterSheet` — the stat block is the whole of its answer, the
same principle as its Defesas. Pass `null` for the total:

```java
hiding.resolveDetection(hider, goblin, null, hiderContext);
```

Author one on the templates that need it; it is deliberately **not** derived from the creature's
own Atenção Graduação, for the same reason its DF is not derived from its Destreza:

```java
AbstractMonsterTemplate.builder().name("Sentinela").perception(19). ... .build();
```

The 14 default is an inference, not authored — no stat block in `docs/rules/` carries an Atenção
column, and 14 is where an unremarkable creature's own roll would land on average.
`GenericMonster` authors 12 / 13 / 14 / 16 / 24 across its five tiers.

Existing templates and every `MonsterSheet.of(...)` overload are unchanged — the column is
defaulted on both.

**A tie sees through**, the same reading of a tie `InteractionResult#getSucceeded()` and
`AttackReceiver` already take. A `null` total from a *rolling* watcher is "cannot tell" and sees
nothing, rather than seeing everything.

## 5. Giving yourself away — `RevealTrigger`

```java
boolean reveals(CombatantSheet hider, RevealTrigger trigger);   // would it? — ask before committing
boolean reveal (CombatantSheet hider, RevealTrigger trigger);   // do it; false when it wouldn't
```

Three constants, each ending the **whole** concealment for every watcher at once — what was given
away was the hiding place, not one creature's line of sight:

| Trigger | Rule |
|---|---|
| `ATTACK` | An attack of any sort, **a Magia that deals damage included**. Never excused. |
| `SKILL_ROLL_ON_ANOTHER` | Any Perícia roll aimed at another combatant. A self-targeted roll is not one, and you simply don't report it. |
| `MOVEMENT` | Moving. Excused by `MobilidadeFeat#MOVIMENTO_FURTIVO` through the new `Feat#movesWhileHidden(Character)` hook. |

**Nothing fires these for you.** `AttackDelivery`, `SpellCastingService` and `MovementService`
stay report-only, exactly as they were — the caller that resolved the action reports the
give-away, the same caller-driven discipline `DefeatBlessingService` and
`ChargeService#applyOutcome` already keep.

**Which trigger a Perícia roll counts as is yours to decide, and that isn't a formality.**
`CombatantAction` records the Perícia, the governing Atributo and the `AttackSource` — but no
target — so this core genuinely cannot tell a self-buff from a roll made at somebody else. You
passed that target into `applyTo`; you know.

## 6. `MobilidadeFeat#MOVIMENTO_FURTIVO` — permission real, price still not

"Você pode se mover enquanto furtivo, mas seu Movimento Base é reduzido à metade."

The **permission** now works: its holder moves and stays Escondido. The **price** does not —
halving Movimento Base needs a multiplicative stage `MovementService` doesn't have (it sums
additively, and a `MOVEMENT_HALVED` `ModifierType` is explicitly not the fix). So the Talento
currently grants its benefit and charges nothing for it. Budget accordingly if you surface it.

`AssassinoFeat#ESCUDO_DE_SOMBRAS` (+3 às Defesas e RDS enquanto escondido) was already wired to
read the Condição off the sheet — it is reachable for the first time now that something applies
one.

## 7. What this deliberately does not do

- **It does not gate hiding.** Furtividade's own text forbids hiding while observed
  (`FurtividadeCompetencyAbility#AGORA_ESTOU_AGORA_NAO_ESTOU` lifts it at +1 nível), but "currently
  observed" is not a state this core holds — `isHiddenFrom` answers only who is fooled by an
  *existing* concealment. `hide` accepts any roll; the Narrador adjudicates.
- **It measures nothing.** No distance, cover, lighting or Terreno term reaches the GD. This core
  does no geometry, and the Furtividade total is taken as the whole of the concealment.
- **It grants no bonus.** What being Escondido is *worth* belongs to whichever trait says so.
- **A `SkillCompetencyAbility` still can't read its own holder's Condição**, which is what keeps
  `FurtividadeCompetencyAbility#ACAO_SURPRESA` and `#MORTE_OCULTA` inert. A `Feat` can.

## 8. How to perform an Investida

An Investida is a movement and an Ataque Corpo-a-Corpo bought as one action. Four steps, and step 3
is an **ordinary attack** — that is the whole design.

```java
ChargeService charge = new ChargeServiceImpl();

// 1. Ask whether they may charge at all, and what it will cost.
//    A null weapon is an Ataque Desarmado and is a legitimate charge.
if (!charge.canCharge(knight, lance)) { /* offer something else */ }

// 2. Declare it. This claims the Rodada's movement and tells you everything
//    resolved about the manoeuvre — but it does NOT attack.
SceneContext context = scene.buildContext(knight, distances);
ChargeResult declared = charge.begin(knight, lance, context);

declared.actionCost();                                // 3PA, less any Talento that shortens it
declared.movementAllowanceInUnidadesDeDistancia();    // how far they may travel, in UD
declared.provokedReactors();                          // who may react — see §10
declared.unappliedMovementDamageReduction();          // see §11
```

You move the character that far (this core does no geometry — the distance is yours to apply), and
then attack. **Nothing about step 3 is charge-specific except the marker and the cost:**

```java
// 3. An ordinary attack, carrying the manoeuvre on its roll.
SkillRoll roll = new SkillRoll(List.of(5, 4, 3), null, null,
                               declared.actionCost(), Manoeuvre.INVESTIDA);

DeliveredAttackResult result = new AttackDelivery().resolve(
        DeliveredAttack.from(dragon, DefenseType.PHYSICAL)
                .attacker(knight)
                .attackSkill(SkillType.ATAQUE_CORPO_A_CORPO)
                .attackSource(lance)
                .attackRoll(roll)
                .sceneContext(context)
                .build());

// result.getAttackResult().getDamageBonus() already carries the Investida's +2.

// 4. Settle what the outcome costs the charger.
charge.applyOutcome(knight, result.getHit());
```

That last call is the only part you must not forget: `AttackDelivery` is report-only and applies
nothing, so **the miss penalty is yours to apply**, the same caller-driven shape
`DefeatBlessingService#applyDefeatBlessings` already has. On a hit it is a no-op and returns
`null`; on a miss it returns the granted `TemporaryBonus`.

**Passing `Manoeuvre.INVESTIDA` is what makes the attack a charge**, and the marker rides the
`SkillRoll` rather than the `DeliveredAttack` so it also reaches a direct
`new AtaqueCorpoACorpoInteraction().applyTo(...)` call. It is the last parameter of a new longest
`SkillRoll` constructor; every existing constructor delegates into it with `null`, meaning "an
ordinary attack" — never "not a charge".

### Who may charge

`canCharge` / `begin` refuse five ways, each with its own `TranslatableMessages` key:

| Refusal | When |
|---|---|
| `WEAPON_NOT_DRAWN` | the weapon is carried but **sheathed** |
| `WEAPON_NOT_CARRIED` | it is neither in their equipment nor one of their Armas Naturais |
| `CHARGE_REQUIRES_MELEE_WEAPON` | it is not swung as `SkillType.ATAQUE_CORPO_A_CORPO` |
| `CANNOT_ATTACK_WITH_WEAPON` | their current Forma suppresses it |
| `CHARGE_MOVEMENT_PREVENTED` | a Condição forbids moving (Agarrado / Imobilizado) |

Two of those are worth stating plainly:

- **The weapon must already be in hand.** An Investida bundles a movement with an attack and prices
  neither a draw nor a moment to make one, so `WeaponDrawService` is deliberately *not* consulted —
  sacar is a separate action your caller performs first. An **Arma Natural is exempt**, for the
  right reason rather than by special case: it is not equipment, so there is nothing to draw.
- **Melee is the Perícia, never the `ItemCategory`.** That is what lets a Chifres Poderosos charge,
  which Guampo's Chifres Majestosos and the Empalador's Favor both require.

## 9. What an Investida is worth

| | Figure | Where it comes from |
|---|---|---|
| Cost | **3PA** (`BASE_ACTION_POINT_COST`) | **authored** — no rules text prices an Investida. For scale, an ordinary Perícia roll is 2PA. |
| Allowance | **2 × Movimento Base** (`BASE_MOVEMENT_MULTIPLIER`) | read off `DexterityAbility#IMPLACAVEL`'s "o triplo … **ao invés do dobro**" |
| On a hit | **+2** to the dano roll (`HIT_DAMAGE_BONUS`) | authored; numerically `Skill.ADVANTAGE_BONUS` |
| On a miss | **-2** às Defesas for 1 Rodada (`MISS_DEFENSE_MALUS`) | authored, and confirmed by that same clause calling it "o redutor **padrão** de -2" |

**The allowance is a total distance, not a per-Ponto-de-Ação figure.** It is the one deliberate
exception to `MovementService`'s governing rule that every movement figure in this ruleset is per
PA — an Investida is one fixed-cost action, so there is no "how many points do I spend moving"
choice left for you to multiply by. Don't add it to, or compare it against, a Movimento Base.

**The +2 needs no "did it hit" check from you.** It is summed into `DamageBonus` like any other
contributor, and a `DamageBonus` only ever reaches a dano roll — which `AttackDelivery` only builds
a chain for on a hit. A missed charge simply has nothing to spend it on.

**The miss penalty renews rather than stacks.** It is granted as a *sourced* `Blessing`, so a second
failed Investida inside the window refreshes the -2 instead of deepening it to -4. The rules say
nothing about two failed charges; renewal is the conservative reading.

### The hooks a trait modifies it through

Six new hooks, all defaulted — nothing you hold changes behaviour unless it overrides one:

| Hook | Does |
|---|---|
| `Feat#resolveChargeActionPointReduction` | shortens the manoeuvre (floored at 1PA) |
| `Feat#resolveChargeMovementDamageReduction` | RD during the charge's movement (§11) |
| `AttributeAbility#resolveChargeMovementMultiplierIncrease` | ×3 instead of ×2 |
| `AttributeAbility#resolveManoeuvreRollBonus` | a bonus to the charge's Perícia roll |
| `AttributeAbility#waivesChargeMissDefensePenalty` | spares its holder the -2 |
| `AttributeAbility#exemptsFromMovementReactions` | the movement provokes nothing (§10) |

Two catalog entries become real through them. **`DexterityAbility#IMPLACAVEL` is now fully
implemented** — all four of its clauses, every one scoped to its holder's Investidas, including the
Vantagem on the charge's roll. **`MobilidadeFeat#INVESTIDA_AQUATICA`'s second clause** ("o Tempo de
Ação de investidas sempre reduzidos em -1PA") takes its cost to 2PA — ⚠️ **unconditionally**, which
over-grants: the clause is gated on having a *Movimento Base de Natação*, a sub-stat this core does
not model, so there is nothing to test it against. Budget accordingly if you surface it.

## 10. Movement provokes Reações — who may react

This is a **general movement rule**, not an Investida one; the charge is simply the first manoeuvre
modelled that triggers it.

```java
MovementReactionService reactions = new MovementReactionServiceImpl();

// null manoeuvre = an ordinary movement. ChargeResult#provokedReactors() is this call,
// made for you with Manoeuvre.INVESTIDA.
List<CombatantSheet> mayReact = reactions.getProvokedReactors(mover, context, null);
```

An enemy is entitled to react when they hold a **drawn** melee weapon — or an **Arma Natural**,
which cannot be sheathed and so always counts — whose reach covers the distance to the mover.
**Ataque à Distância never provokes one**, at any band: an archer standing next to you is not a
threat under this rule.

- **Drawn, not equipped.** A sword on the belt threatens nobody.
- **Reach is the threatener's own**, from `AttackRangeService` — so a Lança covers a band an adaga
  does not, and a larger creature outreaches a smaller one holding the same weapon.
- **A `null` `SceneContext` yields an empty list.** With no positions known, "cannot tell" reads as
  nobody rather than everybody.

⚠️ **Nothing fires a Reação.** This core has no mechanism for one — `ReactionsService` computes a
combatant's *maximum* and nothing anywhere tracks how many they have spent — so the list is the
**opportunity, not the act**, a reactor's remaining Reações are deliberately not consulted, and the
adjudication is yours. It is also about where the mover stands **now**: a movement's path and
distance are not recorded, so a caller that cares about ground crossed asks once per step.

## 11. What the Investida deliberately does not do

- **It does not spend your Pontos de Ação.** The cost is reported, never deducted — this core runs
  no PA economy, the same standing caveat `WeaponDrawService#draw` carries.
- **It does not move anybody.** `begin` claims the Rodada's movement *count* and reports an
  allowance; applying the distance is yours, as all geometry is.
- **It does not verify the movement happened**, nor in which direction. That is what still blocks
  `NaturalWeapon#CHIFRES_PODEROSOS`'s "atacar após se mover em direção ao alvo".
- **`INVESTIDA_SELVAGEM`'s Redução de Danos is computed but not applied.** It rides
  `ChargeResult#unappliedMovementDamageReduction()` as exact data — one point per Título Aventyr
  held — because "durante o movimento da investida" is a window shorter than a Rodada, the shortest
  a `TemporaryBonus` can last; granting one would go on protecting the charger after the charge had
  landed. Apply it yourself for the duration you adjudicate, or read it and ignore it.
- **No Área de Efeito on a charge**, so `INVESTIDA_SELVAGEM`'s Explosão — and therefore
  `INVESTIDA_SELVAGEM_SOLAR` / `_LUNAR`, which count the enemies it damaged — stay unbuilt.
- **No granted `+1d6`.** `NaturalWeapon#CHIFRES_PODEROSOS`, `Guampo` and the Empalador all state
  one; this core never rolls dice, and a bonus die is not a `DamageBase` scale-up, so there is no
  representation for it. These are no longer blocked on the manoeuvre, only on the die.
- **Reposicionar is still not a manoeuvre.** `Manoeuvre` has one constant on purpose;
  `MobilidadeFeat#MOVIMENTO_RAPIDO` and `#MOVIMENTO_ACROBATICO` are still waiting on it.

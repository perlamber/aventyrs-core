# Changelog — aventyrs-core

Written for projects that consume this library. Everything below is the delta since commit
`1c14563de3119eea68b0c0e73b73b3f2c03a4b25` ("Ego Advantages: Recursos and Sorte domains,
Dynamic Initiative Tracking").

## Unreleased — since `1c14563`

`build.gradle` still declares `version '0.0.15'`; **no version bump has happened yet**, so a
consumer pinning `0.0.15` will see two very different artifacts unless the version is raised
before publishing. The last commit in this range is `457f66c` ("Abilities skills, Title
Abilities requirements"); the Talento (Feat) and Item work below is still **uncommitted in the
working tree**, so it may still shift before release. `./gradlew compileJava` passes on the
current tree.

Commits in range: `1149690`, `a47e8e6`, `183d004`, `99b65f8`, `8d216bf`, `c8d54b2`, `457f66c`,
plus uncommitted work.

## 1. Breaking changes

### 1.1 `InitiativeBlessing` deleted — use `Blessing`

`org.aventyrs.core.sheet.InitiativeBlessing` **no longer exists**. It was generalized into
`org.aventyrs.core.sheet.Blessing`, now used by *both* the initiative-win grant mechanism and
directly-activated Interactions.

| Before | After |
| --- | --- |
| `new InitiativeBlessing(type, value, rounds, appliesToAllies)` | `new Blessing(type, value, rounds, TargetScope, source)` |
| `blessing.isAppliesToAllies()` | `blessing.getScope() == TargetScope.SELF_AND_ALLIES` |
| — | `blessing.getSource()` (new: which trait granted it, e.g. `"DOM_BARDICO"`) |

`boolean appliesToAllies` became a `TargetScope`, and `TargetScope` gained two constants:

```java
public enum TargetScope { SINGLE_TARGET, ALLIES, ENEMIES, SELF, SELF_AND_ALLIES }
```

- `SELF_AND_ALLIES` — the old `appliesToAllies == true` (holder **plus** allies).
- `SELF` — the old `appliesToAllies == false` (holder only).
- `ALLIES` keeps its existing meaning: allies **excluding** the caster (DOM_BÁRDICO).

Any `switch`/`if` over `TargetScope` in a consuming project needs the two new constants
handled. Signatures that changed type accordingly:

- `Scene#applyInitiativeBlessings(CharacterSheet, List<Blessing>)`
- `InitiativeBlessingService#resolveBlessings(Character)` → `List<Blessing>`
- `EgoAdvantage#resolveInitiativeBlessings()`, `AttributeAbility#resolveInitiativeBlessings()`,
  `SkillCompetencyAbility#resolveInitiativeBlessings()` → `List<Blessing>`

(The `InitiativeBlessingService` / `resolveInitiativeBlessings` **names** are unchanged — only
the value type moved.)

### 1.2 `InteractionResult`: four temporary-bonus fields replaced by one `blessings` list

Removed: `temporaryBonusValue`, `temporaryBonusModifierType`, `temporaryBonusRounds`,
`temporaryBonusScope`. Added: `List<Blessing> blessings`.

```java
// before
if (result.getTemporaryBonusValue() != null) {
    sheet.grantTemporaryBonus(result.getTemporaryBonusModifierType(),
                              result.getTemporaryBonusValue(),
                              result.getTemporaryBonusRounds());
}

// after
if (result.getBlessings() != null) {
    for (Blessing b : result.getBlessings()) {
        sheet.grantTemporaryBonus(b.getModifierType(), b.getValue(), b.getRounds());
    }
}
```

`blessings` stays `null` when the Interaction can't grant one at all (same
null-when-not-applicable convention as every other field). The motivation is that a single
Interaction can now report **several** blessings at once (Grito de Guerra Vulcano reports
three), which the old parallel-field shape could not express.

`InteractionResult` also gained `@Builder(toBuilder = true)`.

### 1.3 `DamageService`: `Character`-taking overloads replaced by `CharacterSheet`-taking ones

| Removed | Replacement |
| --- | --- |
| `getTotalAbsoluteDamageReduction(Character, SceneContext)` | `getTotalAbsoluteDamageReduction(CharacterSheet target, SceneContext)` |
| `applyDamage(Character, CharacterSheet, int, boolean)` | `applyDamage(CharacterSheet, int, boolean)` |
| `applyDamage(Character, CharacterSheet, SceneContext, int, boolean)` | `applyDamage(CharacterSheet, SceneContext, int, boolean)` |

A `CharacterSheet` already carries its own `Character` via `getCharacter()`, so the redundant
parameter was dropped. Still present, unchanged: `getTotalDamageReduction(Character)`,
`getTotalAbsoluteDamageReduction(Character)`, `calculateFinalDamage(Character, int, boolean)`
and `calculateFinalDamage(Character, SceneContext, int, boolean)`.

New overloads (see §2.4): `getTotalDamageReduction(CharacterSheet, DamageType, CharacterSheet)`,
`calculateFinalDamage(CharacterSheet, SceneContext, DamageType, CharacterSheet, int, boolean)`,
`applyDamage(CharacterSheet, SceneContext, DamageType, CharacterSheet, int, boolean)`.

`DamageServiceImpl` gained a second constructor
`DamageServiceImpl(ModifierResolver, HitPointsService)`; the existing one-arg constructor now
defaults to `new HitPointsServiceImpl()`.

### 1.4 `org.aventyrs.core.character.Title` deleted

The empty marker interface is gone, replaced by the real Título Aventyr model in
`org.aventyrs.core.title` (§2.1) plus `org.aventyrs.core.character.TitleSlot`. Nothing in
`Character` referenced it before, so this only breaks a consumer that imported the marker
directly.

### 1.5 `Feat` is now an interface, not a Lombok-built class

`org.aventyrs.core.feat.Feat` was a `@Builder @Getter class`; it is now an interface with
`getFeatCategory()`/`getDescription()`/`getFeatRequirements()` and a default
`isEligible(Character)`.

```java
// before
Feat f = Feat.builder().featCategory(FeatCategory.GERAL).build();

// after — generic instance
Feat f = AbstractFeat.builder()
        .featCategory(FeatCategory.GERAL)
        .description("...")
        .featRequirements(FeatRequirements.builder().build())
        .build();
```

### 1.6 `AttributeAbility#resolvePendingSkillTraitChoices` overriders must change signature

The real hook is now `resolvePendingSkillTraitChoices(Collection<SkillType> trainedSkills)`.
The old `resolvePendingSkillTraitChoices(Character)` still exists as a default that delegates
to it, so **callers** are unaffected — but any consumer-defined `AttributeAbility` that
*overrode* the `Character` overload silently stops being called and must be moved to the
`Collection<SkillType>` one.

### 1.7 `DamageBonus` now validates the type/element pairing

The existing `DamageBonus(int value, DamageType type)` constructor now throws
`IllegalOperationException(INVALID_DAMAGE_TYPE_ELEMENT_PAIRING)` when `type` is
`ELEMENTAL` or `FISICO_ELEMENTAL`, because those require an `Element`. Use the new
`DamageBonus(int value, DamageType type, Element element)` for those two types, and keep the
2-arg form for `FISICO`/`MAGICO`/`PRIMORDIAL` (passing an `Element` there throws too).

### 1.8 Enums that grew constants

Exhaustive `switch` statements over these need new branches:

- `TargetScope`: `+ SELF`, `+ SELF_AND_ALLIES`
- `SizeCategory`: `+ PLUS_FIVE` … `+ PLUS_TEN` (previously capped at `PLUS_FOUR`)
- `ModifierType`: `+ DEFESAS`
- `FeatCategory`: `+ ARTE_MARCIAL` (`Type.GERAL`)

## 2. New features

### 2.1 Título Aventyr — new package `org.aventyrs.core.title`

A first-class character concept alongside Race/skills/ego advantages.

- `AventyrTitle` — the per-character **held instance** interface: `getName()`,
  `getBaseEffectDescription()`, `getPrimaryTitleBonusDescription()`, `getSpecializations()`,
  `getAbilities()`, `getAllAbilities()`, `getSpecializationAndSupremaCount()`.
- `AventyrTitleAbility` — Habilidade/Suprema: `getDescription()`, `isSupreme()`, `getPDCost()`,
  `getActionPointCost()`, `isReactionActivation()`, `isFreeActionActivation()`, `isPassive()`,
  `resolveAbsoluteDamageReduction(SceneContext, boolean hasLowerPvAdjacentAlly)`,
  the prerequisite trio `getRequiredSpecializations()`/`getRequiredSpecialization()`/
  `getRequiredOtherAbilities()` plus `isEligible(AventyrTitle)`, and
  `getInteractionClass()` (`Optional<Class<? extends Interaction>>`, **no default** — every
  implementor must answer it).
- `AventyrTitleSpecialization extends AventyrTitleAbility` — an Especialização with a real
  activation cost is an Active Ability too.
- First concrete Título, `org.aventyrs.core.title.santo`: `Santo`, `SantoSpecialization`,
  `SantoAbility`, `AbencoadoPelaLuzAbility`, `AbracadoPelaEscuridaoAbility`, plus two
  activation Interactions — `AbencoadoPelaLuzInteraction` (single-target heal/cure, reports a
  restored resource) and `GritoDeGuerraVulcanoInteraction` (reports three `Blessing`s at once).
  `Santo` exposes `activateAbencoadoPelaLuz(...)`, `activateGritoDeGuerraVulcano(...)`,
  `getDefesasBonus(SceneContext)`, `getPrimaryTitleAllyDefesasBonus(SceneContext)`,
  `getIgnoreCriticalEffectDurationInRounds()`, `grantAbility(...)`.
- `package-info.java` documents the granting API.

**On `Character`** — exactly three slots, not a list:

```java
character.grantTitle(new Santo(...), TitleSlot.PRIMARY);
AventyrTitle primary = character.getPrimaryTitle();   // also getSecondaryTitle/getTertiaryTitle
List<AventyrTitle> held = character.getAllTitles();   // primary first, empty slots omitted
```

**`TitleAbilityService`** (`org.aventyrs.core.character.services`) is the validating entry
point: `grantTitleAbility(Character, CharacterSheet, AventyrTitle, AventyrTitleAbility)`
checks `isEligible` and the Suprema-slot cap and spends XP, throwing
`IllegalOperationException` otherwise; `getAvailableSupremaSlots(Character, AventyrTitle)`
reports remaining slots. `EXTRA_SUPREMA_COST` = 5 XP (Centelha Superior's extra grant).

### 2.2 Talentos (Feats) — `org.aventyrs.core.feat` *(uncommitted)*

- `Feat` interface (§1.5) with default `isEligible(Character)` combining every set
  prerequisite: Attribute `base` threshold, Perícia Graduação threshold (untrained reads as 0),
  and/or another `Feat` already held. Unset prerequisites never block.
- `FeatRequirements` — `@Builder record` of `attributeDomain`, `requiredAttributeValue`,
  `requiredSkillType`, `requiredSkillGraduation`, `requiredFeat`.
- `AbstractFeat` — generic `@Builder` implementation.
- `ArtesMarciaisFeat.ARTISTA_MARCIAL` — first catalog entry (`FeatCategory.ARTE_MARCIAL`), with
  `getDanoBaseBonus(Character)` = +1 plus +1 per held Título.
- `FeatService#grantFeat(Character, CharacterSheet, Feat)` — validates eligibility, spends
  `race.getNewFeatCost(category)` XP, then grants; throws
  `IllegalOperationException(FEAT_PREREQUISITE_NOT_MET)`.
- `Character.feats` is a real **mutable** `List<Feat>` (defaults to a fresh `ArrayList`), with
  `Character#grantFeat(Feat)` as a plain unvalidated mutator.

### 2.3 Roubo de Vida (life steal)

- `org.aventyrs.core.sheet.LifeSteal extends TemporaryEffect` — `new LifeSteal(value,
  Optional<Integer> remainingRounds)`, registered via `CharacterSheet#applyEffect`. It has no
  per-Rodada effect; the value matters only when its holder deals damage.
- `CharacterSheet#getTotalLifeSteal()` sums active instances.
- `LifeStealService#getTotalLifeSteal(Character, CharacterSheet)` adds ability bonuses on top
  (via the new `AttributeAbility#resolveLifeStealBonus()`), returning the base unchanged when
  it is ≤ 0. A caller resolving a dealt hit reads this and applies `CharacterSheet#heal(int)`
  itself — this library still never resolves damage dealt.

### 2.4 Damage typing, elements, and type-scoped RD

- New `org.aventyrs.core.character.Element`: `FOGO`, `AGUA`, `MAGMA`, `ROCHA`, `TERRA`, `GELO`.
- `DamageBonus` carries an optional `Element` (see §1.7 for the pairing rule).
- `DamageService` can now mitigate **per damage type and per attacker**:
  `getTotalDamageReduction(CharacterSheet target, DamageType, CharacterSheet source)`, fed by
  the new `AttributeAbility#resolveDamageReduction(DamageType, CharacterSheet source,
  CharacterSheet target)` hook (`0` by default).
- `DamageInteraction` gained matching overloads carrying `DamageType`/`source` through, so a
  dealt hit's real type and attacker reach mitigation.
- RA now also sums every held Título ability's `resolveAbsoluteDamageReduction(SceneContext,
  hasLowerPvAdjacentAlly)`; `DamageServiceImpl` resolves the adjacent-ally PV comparison itself
  via `SceneContext#getAlliesWithin(Range.ADJACENTE)` + `HitPointsService`.

### 2.5 Margem Crítica widening

`SkillRoll#getCriticalResult(int criticalMarginIncrease)` is new: it lowers the face value that
counts toward an Acerto Crítico Menor (two or more dice at or above
`max(1, 6 - increase)`) instead of hard-coding 6. The no-arg `getCriticalResult()` still exists
and is exactly the zero-widening case, so existing callers are unaffected.

New default hooks feeding it, `0` by default on all three:
`AttributeAbility#resolveCriticalMarginIncrease(SkillType, SceneContext)`,
`EgoAdvantage#resolveCriticalMarginIncrease(...)`,
`SkillCompetencyAbility#resolveCriticalMarginIncrease(...)`.
`AbstractSkillInteraction` sums all three automatically for every skill roll. First real
sources: `DexterityAbility.LETALIDADE_PROGRESSIVA`, `SorteAdvantage.ACE`,
`ArtesAprimorarComArteAbility`'s Margem Crítica Menor branch.

`SorteAdvantage#resolveCriticalMarginIncrease` is no longer declared on that enum alone — it
now overrides the shared `EgoAdvantage` hook, so it participates in the generic scan.

### 2.6 New `AttributeAbility` hooks

All default to a no-op; only override where an ability's rules text calls for it.

| Hook | Purpose |
| --- | --- |
| `resolveGrantedSkillTraining(Character)` | Perícias the ability trains outright on grant |
| `resolvePendingSkillTraitChoices(Collection<SkillType>)` | replaces the `Character` overload (§1.6) |
| `resolvePendingSkillTraitChoiceLimit()` → `OptionalInt` | how many pending choices may actually be resolved |
| `resolvePendingSkillTraitKinds()` → `Set<SkillTraitKind>` | whether the choice is a Especialização, a Habilidade de Competência, or either |
| `resolveRestHitPointsBonus(RestType)` / `resolveRestDeterminationPointsBonus(RestType)` | extra PV/PD on a Rest |
| `resolveLifeStealBonus()` | added to `LifeStealService`'s total |
| `resolveCriticalMarginIncrease(SkillType, SceneContext)` | §2.5 |
| `resolveFirstRollOfTurnBonus(AttributeDomain)` | bonus only on the Turn's first roll of that Attribute |
| `resolveAttributeDomainRollBonus(AttributeDomain, Character)` | bonus to every roll governed by an Attribute |
| `resolveAttributeDomainDifficultyReduction(AttributeDomain, Character)` | GD reduction, same scoping |
| `resolveDamageReduction(DamageType, CharacterSheet, CharacterSheet)` | §2.4 |

`SkillTraitKind` (`org.aventyrs.core.skill`) is the new `SPECIALIZATION` / `COMPETENCY_ABILITY`
enum backing the pending-choice hooks. `AttributeAbilityGrantResult` correspondingly gained
`pendingSkillTraitChoiceLimit` (int, default 0) and `pendingSkillTraitKinds`
(`Set<SkillTraitKind>`, default empty) — **a consumer driving ability grants should read both**,
otherwise it will offer the player more skill-trait choices than the rules allow.

Named limits are exposed as constants: `GnoseAbility.DOMINIO_DO_CONHECIMENTO_CHOICE_LIMIT` (3)
and `GnoseAbility.GENIALIDADE_E_ESFORCO_CHOICE_LIMIT` (2).

### 2.7 Centelha Superior flag on `Character`

`Character#selectCentelhaSuperior()` / `isCentelhaSuperiorSelected()` (default `false`) record
that `InstinctAbility#CENTELHA_SUPERIOR`'s one-time extra-Suprema grant is available;
`TitleAbilityService` consumes it.

### 2.8 `SceneContext` range lookups returning the participants

`getAlliesWithin(Range)` and `getEnemiesWithin(Range)` join the existing
`hasAllyWithin`/`countAlliesWithin` family, returning the matching `CharacterSheet`s themselves
so a caller can inspect each one (PV comparisons, per-ally grants).

### 2.9 `InteractionResult` can report a restored resource

New `resourceGainValue` / `resourceGainType` pair, the mirror of the existing
`resourceLossValue`/`resourceLossType`. First producer: `AbencoadoPelaLuzInteraction`'s heal.

### 2.10 Item scaffolding *(uncommitted, placeholder only)*

`org.aventyrs.core.item` gained an empty `Item` marker interface, `ItemType`
(`OFFENSIVE`/`DEFENSIVE`/`UTILITY`/`CONSUMABLE`) and `ItemCategory` (18 constants, each mapped
to an `ItemType`). No behavior is attached yet — do not build against these expecting a working
Equipamento system.

## 3. Behavior changes (no signature change)

- **A skill roll now mutates the target's `CharacterSheet`.** ~~`AbstractSkillInteraction#applyTo`
  calls `CharacterSheet#consumeFirstRollThisTurn(AttributeDomain)` whenever a `SkillRoll` is
  supplied…~~ **Superseded:** `consumeFirstRollThisTurn` was removed. `applyTo` now
  reads `CombatantSheet#isFirstRollOfTurnFor(AttributeDomain)` — a *non-mutating* check over the
  per-Rodada action log — so previewing a roll no longer consumes the bonus. The API records the
  action afterwards via `CombatantSheet#recordAction`; the log clears at `startNewRound`, with
  `startTurn` marking the per-Turn slice.
- **Skill rolls sum more sources.** Attribute-domain roll bonuses, attribute-domain GD
  reductions, first-roll-of-Turn bonuses and Margem Crítica widening are all now folded in
  automatically for every Perícia.
- **Rest recovery includes ability bonuses.** `RestServiceImpl`'s PV/PD recovery adds
  `resolveRestHitPointsBonus`/`resolveRestDeterminationPointsBonus` on top of the
  Vigor/Instinto-derived amount.
- **`Scene#next()` no longer calls `startTurn` twice at a round boundary** (`1149690`). The
  first participant of a new Round previously received a redundant `startTurn` before the
  normal one.
- **`ArtesInteraction`** reports DOM_BÁRDICO through `blessings` instead of the removed
  singular fields; the computed value/duration/scope are unchanged.
- **Race javadoc only** — `Flaminideo`, `Gorgona` and `Orc` had TODO citations rewritten to
  point at the gaps that actually remain now that Títulos/Elements/type-scoped RD exist. No
  behavior changed.

## 5. Migration checklist

1. Replace every `InitiativeBlessing` with `Blessing`; translate `appliesToAllies` to
   `TargetScope.SELF_AND_ALLIES` / `TargetScope.SELF`, and pass a `source` string.
2. Replace `InteractionResult.getTemporaryBonus*()` reads with a loop over `getBlessings()`.
3. Drop the leading `Character` argument from `DamageService#applyDamage` and
   `#getTotalAbsoluteDamageReduction(…, SceneContext)` calls.
4. Swap `Feat.builder()` for `AbstractFeat.builder()`.
5. Move any consumer-defined `AttributeAbility` override of
   `resolvePendingSkillTraitChoices(Character)` onto the `Collection<SkillType>` overload.
6. Pass an `Element` when constructing a `DamageBonus` of type `ELEMENTAL`/`FISICO_ELEMENTAL`.
7. Extend exhaustive switches over `TargetScope`, `SizeCategory`, `ModifierType` and
   `FeatCategory`.
8. Add the seven new message keys to translation bundles.
9. If you drive ability grants, honour `AttributeAbilityGrantResult`'s new
   `pendingSkillTraitChoiceLimit` and `pendingSkillTraitKinds`.

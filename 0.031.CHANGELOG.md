# Changelog — aventyrs-core 0.0.31

Written for projects that consume this library. This release has **five themes**:

- **Part I (§1–§4)** — `Feat#resolveAttributeBonus` now reaches **every** derived Atributo total
  (PV/PM/PD, Defesa, Conjuração, Requisitos de Item, Rest, the melee ½-Força term), not just the
  Perícia-roll path, through the new `Character#getEffectiveAttributeTotal`. Plus four new `Feat`
  hooks and `Character#getAttributeAbilities()` becoming a live aggregate.
- **Part II (§5–§7)** — a **start-of-combat trigger** (`CombatStartBlessingService`), the
  **Resistência a Críticos** stat (`ModifierType.CRITICAL_RESISTANCE`), a round-scoped RD grant
  finally being summed, and **`MimetizedSpell`** / `MimetizedSpellCastingService`.
- **Part III (§8–§10)** — **`Alignment` replaces `Character.tendencia`.** *This is the one
  source-breaking change in the release.*
- **Part IV (§11–§13)** — **`SceneContext#environmentalState`** (lighting, altitude, flight,
  submersion) and the four Elfo **Guardião** Talentos becoming real.
- **Part V (§14–§16)** — **Título acquisition gating** (`TitleAcquisitionService`) and
  **per-character prerequisite creature types**.

`./gradlew test` passes on the current tree (`build -x javadoc` green). ~90 tests are new across
this range, in 5 new test classes plus additions to `RacialFeatEffectIntegrationTest`,
`FeatServiceImplTest`, `AbstractSkillInteractionTest`, `DamageServiceImplTest`,
`FeatRequirementsGateTest`, `CharacterTest`.

**One source-breaking change** (§8), plus one new `ModifierType` constant (§5) and several
`default`-only interface additions. An outside `Feat` / `AventyrTitle` implementation keeps
compiling untouched.

# Part I — full effective attribute totals, and five new `Feat` hooks

## 1. Breaking changes

**None for a consumer.** `Character#getAttributeAbilities()` still returns
`List<AttributeAbility>`; only *what it contains* changed (§3). Every new `Feat` method is a
`default`.

| Interface | Added | Consequence for an outside implementor |
|---|---|---|
| `Feat` | `default boolean resolveAutomaticSuccess(SkillType, int targetValue, SceneContext, Character)` → `false` | none |
| `Feat` | `default List<EffectChain> resolveEffectChains(Character, SkillType, AttackSource)` → `List.of()` | none |
| `Feat` | `default int resolveGrantedLifeSteal(Character)` → `0` | none |
| `Feat` | `default List<AttributeAbility> getGrantedAttributeAbilities(Character)` → `List.of()` | none |

## 2. `Character#getEffectiveAttributeTotal(AttributeDomain)`

The single answer to "what is this character's Vigor/Força/… *total*, right now". It is
`AttributeValue#getTotal()` (base + racial + variable) **plus every held Talento's
`Feat#resolveAttributeBonus` grant** (`VampiricoFeat#MESTRE_VAMPIRO`, the seven `BestialFeat`
Heranças, `AnaoFeat#CONSELHEIRO_DE_GUERRA_YMIRIANO`'s +1 Gnose).

**Before this release** a permanent `Feat` Atributo grant reached only a Perícia roll. Now it
also reaches — with no change at any call site:

- PV / PM / PD (`HitPointsService`, `MagicPointsService`, `DeterminationPointsService`)
- DF / DM (`DefenseService`, via `EsquivaEApararInteraction`)
- Conjuração
- `ItemRequirements#isMetBy` — an item's Favor now applies if a Talento pushes you over the bar
- `RestService`
- the melee ½-Força dano term (`AbstractSkillInteraction#resolveMeleeStrengthDamage`)

`AttributeValue#getBase()` readers deliberately **do not** call it — the Graduação cap, the
Habilidade slot count, `FeatRequirements`, `CharacterAttributeService#upgradeBase` — those gate
on invested base. Round-scoped `ModifierType.<ATTR>_BONUS` `TemporaryBonus`es are still read
only on the Perícia-roll path (that needs a `CombatantSheet` this method has no access to).

**Consumer impact:** a character sheet holding one of those Talentos will now report slightly
higher PV/PM/PD/Defesa than it did on 0.0.30. If you cached those numbers, recompute.

## 3. `Character#getAttributeAbilities()` is now a live aggregate

It returns the acquired list **plus** every held Talento's `getGrantedAttributeAbilities(this)`,
deduplicated — the same live-aggregation shape `getActiveAbilities()` / `getNaturalWeapons()`
already had. `AnaoFeat#CONSELHEIRO_DE_GUERRA_YMIRIANO`'s free Habilidade de Força is the first
consumer.

- **New: `Character#getAcquiredAttributeAbilities()`** — the raw builder list, without the
  granted ones. `AttributeAbilityServiceImpl` validates slot use against *this* one, so a
  Talento-granted Habilidade never eats a paid slot.
- A Talento-granted ability contributes **only its passive / `resolve*` hooks** — not the
  one-time acquisition side-effects `AttributeAbilityService` runs (a copied `ActiveAbility`, a
  permanent Ego point, granted Perícia training). Every shipped `StrengthAbility` is passive, so
  this bites only if the hook is later reused for an Atributo whose Habilidades aren't.

**Consumer impact:** if you serialise `character.getAttributeAbilities()`, a
`CONSELHEIRO_DE_GUERRA_YMIRIANO` holder now lists one extra Habilidade. Read
`getAcquiredAttributeAbilities()` for the "what did the player pay for" list.

## 4. The four new `Feat` hooks

| Hook | Live consumer | Notes |
|---|---|---|
| `resolveAutomaticSuccess(skillType, targetValue, sceneContext, character)` | `ElficoFeat#SENTIDOS_ABSOLUTOS` (Atenção) | only consulted when the caller supplied a target GD; a roll against no target stays unresolved, never "succeeded" |
| `resolveEffectChains(attacker, attackSkill, attackSource)` | `ElficoFeat#CORRUPTOR_SOMBRIO`'s Definhar | `AttackDelivery` merges these with the caller-supplied chains, applied only when the Corrente threshold is met |
| `resolveGrantedLifeSteal(character)` | `ElficoFeat#CORRUPTOR_SOMBRIO` ("Roubo de Vida 1") | establishes Roubo de Vida from nothing, unlike `resolveLifeStealBonus` which only amplifies. Summed by `LifeStealService#getTotalLifeSteal` |
| `getGrantedAttributeAbilities(character)` | `AnaoFeat#CONSELHEIRO_DE_GUERRA_YMIRIANO` | see §3 |

New choice-carrying class: **`ConselheiroDeGuerraYmirianoFeat`** (`AbstractFeat`, records the
picked `StrengthAbility`) — same catalog-vs-acquired split as `FocoEmPericiaFeat`. Grant it in
place of the bare `AnaoFeat.CONSELHEIRO_DE_GUERRA_YMIRIANO` constant:
`featService.grantFeat(character, sheet, ConselheiroDeGuerraYmirianoFeat.of(character, StrengthAbility.DESTRUIDOR_DE_MUROS))`.

# Part II — start-of-combat blessings, Resistência a Críticos, mimetized spells

## 5. `ModifierType.CRITICAL_RESISTANCE` — the one enum addition

**Resistência a Críticos (RC)** — a *defender-side* narrowing of an attacker's Margem Crítica
Menor. Per `docs/rules/defesas-e-resistencias.txt` one instance is worth `2` (a −2 to the
attacker's Margem Crítica Menor).

`AbstractSkillInteraction` subtracts the **attack target's**
`getTemporaryBonus(CRITICAL_RESISTANCE)` from the attacker's summed Margem Crítica Menor
widening, before `SkillRoll#getCriticalResult`. Because `AttackDelivery` routes through that
interaction, RC covers a delivered attack too. It is **not** read on the `AttackReceiver` mirror
(the attacker rolls nothing there).

Only a *round-scoped* grant (a `Blessing`/`TemporaryBonus`) is read today. Still not modelled,
and TODO'd on the relevant constants: the "−1 à Margem Crítica Maior" clause (this ruleset
models no Acerto Crítico Maior margin), "não-PRIMORDIAL" scoping, a floor below the attacker's
own baseline margin, and a *permanent* RC source (`MonstruosoFeat`, `ElementalFeat`,
`GorgonaFeat`, `Troll`, `ProfissaoCompetencyAbility`) — each blocked on a form state besides.

> **Consumer note:** if you `switch` exhaustively over `ModifierType` without a `default`, add a
> `CRITICAL_RESISTANCE` arm.

## 6. `CombatStartBlessingService` — a start-of-combat trigger

New in `org.aventyrs.core.character.services`. Exact mirror of `DefeatBlessingService`:
caller-driven, because this core has no combat observer.

```java
// when your caller turns the Cena into a Cena de Combate (the same place it calls
// Scene#setCombatScene(true)):
new CombatStartBlessingServiceImpl().applyCombatStartBlessings(combatantSheet);
```

It scans the combatant's held Talentos for `Feat#resolveCombatStartBlessings(Character)` (new
`default` → `List.of()`) and applies each `Blessing` as a `TemporaryBonus` on that sheet. Every
such Blessing is `TargetScope.SELF`.

**`AnaoFeat#VIGOR_DO_INVERNO` is now fully real** — its "No início de cada combate você recebe
RD e Resistência a Críticos por uma quantidade de Rodadas igual à metade de seu Multiplicador
de PV" grants two Blessings (`DAMAGE_REDUCTION` at `DamageService.DEFAULT_DAMAGE_REDUCTION`, and
`CRITICAL_RESISTANCE` at `2`), each lasting `HitPointsService#getLifeMultiplier / 2` Rodadas
(floored, the Talento's own +1 to the multiplier included).

## 7. A round-scoped RD grant is now summed; and `MimetizedSpell`

- **`DamageService#getTotalDamageReduction(CombatantSheet, DamageType, CombatantSheet)`** (and
  the `DamageDescriptor` overload) now add `target.getTemporaryBonus(ModifierType.DAMAGE_REDUCTION)`.
  A `Blessing`/`TemporaryBonus` of RD was previously inert. **The `Character`-only overload still
  cannot see it** (no sheet) — same split the aggregate Pontos de Ação / Reações reads carry.
- **`MimetizedSpell`** (`org.aventyrs.core.magic`) — a Magia a Talento lets a character cast
  *without learning it*: it keeps the catalog `Spell` and overrides only a Determinação cost and
  optional activation-time / duration / self-only constraints. Deliberately **not** a `Spell` —
  it lives in `Character#mimetizedSpells` (fed live by `Feat#getGrantedMimetizedSpells`), never
  in `Character#spells`, so mimicry can't satisfy a Magic Tree's cap/climb/branch gate.
- **`MimetizedSpellCastingService#cast(CombatantSheet caster, MimetizedSpell)`** (new, §II) —
  validates the caster holds that exact `MimetizedSpell`, spends its PD via
  `CombatantSheet#spendDeterminationPoints`, returns a `MimetizedSpellCastingResult` with the
  effective terms. Resolving the catalog effect is deliberately a later pipeline.
  Throws **`MIMETIZED_SPELL_NOT_HELD`**.

# Part III — `Alignment` replaces `Character.tendencia`

## 8. Breaking change

**`Character.tendencia` (an unvalidated `int` on a 1–10 scale) is removed.** In its place:

| Removed | Added |
|---|---|
| `int Character#getTendencia()` | `Alignment Character#getAlignment()` |
| `Character.builder().tendencia(int)` | `Character.builder().alignment(Alignment)` |
| default `6` | default `Alignment.NEUTRAL` |

**`Alignment`** (`org.aventyrs.core.character`) is a three-value enum: `GOOD`, `NEUTRAL`, `EVIL`.

**Any consumer that reads or sets `tendencia` on a core `Character` must migrate.** A consumer
that keeps its own `tendencia` DTO field (an API wire shape, a client model) is free to keep
it — but the mapping layer where it meets `Character.builder()` / `Character#getTendencia()` is
where the change bites. Map your `int` to an `Alignment` (or expose `Alignment` end-to-end).

## 9. `FeatRequirements.requiredAlignments`

New record component: `Set<Alignment> requiredAlignments`. An unset or empty set means "no
alignment prerequisite" (the default for every existing constant). A non-empty set means the
holder's `getAlignment()` must be one of them.

Live consumer: **`ElficoFeat#CORRUPTOR_SOMBRIO`** — `requiredAlignments(Set.of(NEUTRAL, EVIL))`,
its "apenas personagens de tendência neutra ou maligna" clause, previously unenforced.

`Feat#isEligible` gained an `alignmentSatisfied` clause; grant validation still reuses
`FEAT_PREREQUISITE_NOT_MET`.

## 10. What did **not** change

Races still don't constrain alignment — `Anao` / `Gorgona`'s "raramente pick extremist
tendências" advisory text maps onto nothing, same as before. There is still no faction /
allegiance concept.

# Part IV — environmental state, and the Elfo Guardiões

## 11. `SceneContext#environmentalState`

New field, type **`EnvironmentalState`** (`org.aventyrs.core.scene`) — a record:

```java
record EnvironmentalState(LightLevel lightLevel, Altitude altitude,
                          boolean flying, boolean atLeastHalfSubmerged)
```

- **`LightLevel`** — `DARK` / `SHADOWED` / `NORMAL` / `BRIGHT`, with `isDarkOrShadowed()`.
- **`Altitude`** — `ORDINARY` / `HIGH`.
- `EnvironmentalState.ORDINARY` is the constant every shorter `SceneContext` constructor uses.

**No breaking change.** A new longest constructor takes the `EnvironmentalState` as a trailing
argument; every existing constructor delegates with `EnvironmentalState.ORDINARY`. New getter
`SceneContext#getEnvironmentalState()` (never `null`).

**To use it:** build your `SceneContext` with the 10-arg constructor and pass the actor's
resolved lighting / altitude / flight / submersion. Lighting and altitude describe the actor's
surroundings; flight and submersion describe the actor.

## 12. The four Guardião Talentos are real

`ElficoFeat`'s `GUARDIAO_DOS_BOSQUES` / `GUARDIAO_DAS_DUNAS` / `GUARDIAO_DAS_NUVENS` /
`GUARDIAO_DAS_PROFUNDEZAS` now resolve their Vantagem:

| Talento | Condition | Also |
|---|---|---|
| Bosques | `TerrainType.FOREST` | mimetizes Cativar Animal (2PD); prohibits Título Bruxo |
| Dunas | `TerrainType.DESERT` | mimetizes (Dádiva de Undine — not in catalog, TODO); prohibits Bruxo |
| Nuvens | `EnvironmentalState.altitude() == HIGH` **or** `flying()` | mimetizes Voo on self (1PA, 2 Rodadas, 3PD) |
| Profundezas | `EnvironmentalState.atLeastHalfSubmerged()` | grants underwater breathing (§13); mimetizes Regeneração (2PD); prohibits Bruxo |

**`CORRUPTOR_SOMBRIO`** now grants Vantagem while `lightLevel().isDarkOrShadowed()` and
Desvantagem while `BRIGHT` (plus its already-real Roubo de Vida 1 and Definhar chain, and it
*allows* the Bruxo Título — §15).

## 13. Guardião eligibility, and underwater breathing

- **Guardião count is capped by race, not a `requiredRace` clause.** `ElficoFeat#isEligible`
  now allows at most **2** Guardião Talentos for an `Elfo`, **1** for a `MeioElfo`, **0**
  otherwise. The bare `.requiredRace(Elfo.class)` on the four constants is gone.
- **`Feat#allowsUnderwaterBreathing(Character)`** (new `default` → `false`) →
  **`Character#canBreatheUnderwater()`**. `GUARDIAO_DAS_PROFUNDEZAS` returns `true`.

# Part V — Título acquisition gating, per-character creature types

## 14. `TitleAcquisitionService`

New interface + `…Impl` in `org.aventyrs.core.title`. A **validated** entry point for granting
a Título, the mirror of `FeatService#grantFeat`:

```java
new TitleAcquisitionServiceImpl().grantTitle(character, title, TitleSlot.PRIMARY);
// throws IllegalOperationException(TITLE_ACQUISITION_PREVENTED) if a held Talento forbids it
```

`Character#grantTitle(AventyrTitle, TitleSlot)` stays the unvalidating mutator for builder /
fixture assembly, same as every other progression invariant.

Supporting additions:

- **`AventyrTitle#getIdentity()`** — new `default` → `Optional.empty()`. A Título's named
  identity when a rule distinguishes it from its `TitleArchetype`. An outside `AventyrTitle`
  implementation is unaffected.
- **`TitleIdentity`** enum — sparse by design, one value so far: `BRUXO`.
- **`TitleAcquisitionPermission`** enum — `NO_OPINION` / `PROHIBIT` / `ALLOW`, with `merge`:
  an explicit `ALLOW` from one held Talento overrides a `PROHIBIT` from another.
- **`Feat#resolveTitleAcquisitionPermission(Optional<TitleIdentity>, Character)`** — new
  `default` → `NO_OPINION`. The four Guardiões return `PROHIBIT` for `BRUXO`;
  `CORRUPTOR_SOMBRIO` returns `ALLOW` for `BRUXO` (its "perde a limitação racial para adquirir o
  Título Bruxo").

New message: **`TITLE_ACQUISITION_PREVENTED`**.

## 15. Per-character prerequisite creature types

- **`Feat#getGrantedPrerequisiteCreatureTypes(Character)`** — new `default` → `Set.of()`.
- **`Character#getPrerequisiteCreatureTypes()`** — the Race's own
  `getPrerequisiteCreatureType()` **plus** every held Talento's grant, as an unmodifiable
  `Set<CreatureType>`. It does **not** change `Race#getCreatureType()` — the creature's true
  identity is unchanged.
- **`Feat#isEligible`**'s `requiredCreatureType` check now tests membership of that set instead
  of equality with the Race's single type.

Live consumer: **`ElficoFeat#ALMA_FEERICA`** grants `CreatureType.FEERICO`.

## 16. Migration checklist

1. **`Alignment` (§8) is the only thing you must change.** Replace `Character#getTendencia()`
   with `getAlignment()` and `builder().tendencia(int)` with `builder().alignment(Alignment)`.
   If you carry a `tendencia` wire field, decide the `int ↔ Alignment` mapping at the boundary.
2. **Recompute cached PV/PM/PD/Defesa** for any sheet holding a Talento with a permanent
   `resolveAttributeBonus` grant (§2).
3. **`CRITICAL_RESISTANCE` (§5)** — add an arm if you exhaustively `switch` `ModifierType`.
4. **New services are opt-in.** `CombatStartBlessingService` (call it when combat starts),
   `MimetizedSpellCastingService`, `TitleAcquisitionService` — nothing calls them for you, and
   nothing breaks if you don't.
5. **`SceneContext` (§11)** — keep using your current constructor; environment defaults to
   `ORDINARY`. Move to the 10-arg form only when you want the Guardião / Corruptor Sombrio
   bonuses to resolve.
6. **New failure modes to surface:** `TITLE_ACQUISITION_PREVENTED` (only via
   `TitleAcquisitionService`), `MIMETIZED_SPELL_NOT_HELD` (only via `MimetizedSpellCastingService`).
7. **`FeatCatalog` size assertions** — unchanged. No new enum constants; `ConselheiroDeGuerraYmirianoFeat`
   is a class, not listed.

# Changelog — aventyrs-core 0.0.23

Written for projects that consume this library. Everything below is the delta since commit
`460191a` ("Spells").

> **Version-string note.** `build.gradle` declares `version '0.0.23'` as of this release. Be aware
> that **0.0.22 shipped without a changelog** — it was set in `efbbdcf` ("java 21 and readme") and
> covers the Talento catalog, the 145-Magia catalog, `AttackSource` and `DamageBase` work across
> `1884fb0`…`460191a`. That omission is pre-existing and is not addressed here; this document
> covers the races range only.

This version has one theme: **eight new playable Raças**, taking the catalog from 21 to 29. Three
of the eight are the first races to reach past the Atributo/Tamanho hooks into real combat
mechanics — a Goblin's dano roll swings with how close its allies are, a Guampo actually takes one
less damage per hit, a Troll actually shrugs off Sangramento — and making those three arrive
required one new `Race` hook and one fix to a service scan that had been silently dropping racial
abilities.

**There are no breaking API changes** (§1), but there are two behaviour changes worth reading if
you author your own `Race` implementations.

`./gradlew test` passes on the current tree — 2128 tests, 106 of them new — apart from two
pre-existing failures unrelated to this range (see §6.1).

---

## 1. Breaking changes

**None.** Both interface additions are `default`, so an outside implementation of `Race` keeps
compiling and simply grants nothing:

| Interface | Added | Consequence for an outside implementor |
|---|---|---|
| `Race` | `default Set<CriticalEffectType> getCriticalEffectImmunities()` | none — defaults to `Set.of()` |

`AbstractCombatantSheet#getCriticalEffectImmunities()` keeps its signature and its `@Override`;
only what it returns changed (§3.1).

Two **behaviour** changes can move numbers without moving any signature — §3.1 and §3.2. Neither
affects a consumer using only the races this library ships, because before this release no `Race`
granted RD, RA or a critical-effect immunity at all.

## 2. New features

### 2.1 Eight Raças

| Race | `CreatureType` | Shape | Atributos Raciais | Tamanho |
|---|---|---|---|---|
| `NascidoDoDragao` | HUMANOIDE | bespoke Mestiço | +1 Força, +1 Foco (+1 herdado) | parent +1 |
| `Aviano` | MONSTRUOSO | `Subtipo` choice | +1 Destreza, +1 Força *or* Vigor | 0 |
| `Goblin` | MONSTRUOSO | stateless | +1 Destreza, +1 choosable Foco/Gnose | −1 |
| `Ogro` | MONSTRUOSO | `Aptidao` choice | +2/+1 *or* +1/+2 Força/Destreza | +1 |
| `Guampo` | MONSTRUOSO | stateless | +1 Gnose, +1 Instinto | +1 |
| `Indomito` | MONSTRUOSO | `Tribo` choice | +1 Força, +1 per tribo | 0 |
| `Troll` | MONSTRUOSO | stateless | +2 Força | 0 |
| `HomemFera` | HUMANOIDE | `EspiritoAnimal` choice | +1 Instinto | 0 |

```java
Race race = new Aviano(Aviano.Subtipo.RAPINANTE);
Character character = race.generateEmptyCharacter(List.of())
        .player(player).name("Kesh").race(race)
        .attributes(attributes).egos(egos).actionProfile(profile)
        .build();
```

Gnolls are **deliberately absent**: the source document marks the entry `(pendente)` and states no
Atributos, Tamanho or Características at all.

### 2.2 Acquisition-time choices are nested enums, not choosable points

Four of the eight carry a choice the player makes once at creation, held as a constructor field —
the `ArtesAprimorarComArteAbility` pattern, not `AcquiredChoice`, because the choice feeds the race
object's *own* `getFixedAttributeBonuses()`:

```java
new Aviano(Aviano.Subtipo.RAPINANTE);          // or CORRENUVENS
new Ogro(Ogro.Aptidao.FORCA_BRUTA);            // or AGILIDADE_BRUTA
new Indomito(Indomito.Tribo.APEDEMAK);         // BASTET, SACMIS, IMPURO
new HomemFera(HomemFera.EspiritoAnimal.WEMIC); // 7 spirits
```

**Why enums rather than `getChoosableAttributeBonusPoints()`.** An Ogro's rules text offers exactly
two packages — "+2 Força e +1 Destreza; ou +1 Força e +2 Destreza". Modelled as 3 free points over
{Força, Destreza}, `CharacterCreationServiceImpl.allocateAttributes` would happily accept +3/+0,
which the clause does not offer. Two constants say exactly what is on the table. `Goblin`, whose
clause genuinely *is* one free point between two Atributos, uses the choosable-points hook
instead — the two shapes are not interchangeable.

`Indomito.Tribo.IMPURO` merges its second Força point into a single map entry, so
`getFixedAttributeBonuses()` reads `{STRENGTH=2, VIGOR=1}` exactly as its text states ("para um
total de Força +2") rather than as two separate entries.

### 2.3 `NascidoDoDragao` — the second bespoke Mestiço

It follows `MeioElfo`, not `AbstractMesticoRace`: that base is the shared shape of the 6 Mestiços
Elementais (a parent-conditional "+2, ou +3" bonus, Físico Mortal, a size offset off a fixed
attribute pair), and a Nascido do Dragão shares none of it.

```java
new NascidoDoDragao(new Anao(), ElementalType.TERRA,
        AttributeDomain.VIGOR,                              // Atributo Herdado, optional
        List.of(AnoesRacialAbility.FILHOS_DA_MONTANHA));    // Mestiço Humanoide, up to 2
```

Constructor-enforced, all throwing `IllegalOperationException`:

- `INVALID_PARENT_RACE` — a Mestiço parent, a non-Humanoide parent, or an Atributo Herdado the
  parent does not itself grant.
- `INVALID_INHERITED_RACIAL_ABILITIES` — more than 2, or one the parent does not have.
- `INVALID_ELEMENTAL_LINEAGE` — see §4.

**Escamas Cromática is modelled as a pair, and only the pair.** The chosen Elemento and the one it
is vulnerable to are exact data:

```java
race.getElementalLineage();        // ElementalType.TERRA
race.getOpposedElementalType();    // ElementalType.AR — derived, never stored
```

The 8-row opposition table (Fogo↔Água, Magma↔Gelo, Terra↔Ar, Natural↔Eletricidade) is symmetric
and lives private to the race rather than as a `getOpposite()` on `ElementalType`: this is the only
rules text in the codebase stating an opposition, so promoting it would be building a shared
mechanism for its first consumer. **Neither side reaches a damage calculation** — see §6.2.

Two source-document naming quirks are carried rather than corrected: the table writes *Vento* in
one row and *Ar* in another for the same element (`ElementalType.AR` covers both), and *Natural*
appears as an Elemento Base while also being a `MagicType`.

### 2.4 Four new `*RacialAbility` enums

Six now exist in total. All are ordinary `SkillCompetencyAbility` instances, so
`AbstractSkillInteraction.allSkillCompetencyAbilities` picks them up with no Interaction-specific
code.

**`AvianosRacialAbility.VISAO_ALEM_DO_ALCANCE`** — a flat `@Modifier(ATTENTION_ROLL_BONUS)` of
`Skill.ADVANTAGE_BONUS`, the same shape as `ElfosRacialAbility.SENTIDOS_ABSOLUTOS`. One documented
over-grant: the clause scopes the Vantagem to "percepções visuais", and this core does not track
what a roll is *for*, so it applies to every Atenção roll — the identical simplification
`DirigirECavalgarCompetencyAbility.CONTROLAR_ANIMAIS` already makes.

**`GuamposRacialAbility.VIGOR_DE_EPONA`** — a flat `@Modifier(DAMAGE_REDUCTION)` of 1. The literal
1 rather than `DamageService.DEFAULT_DAMAGE_REDUCTION` (+2), because that constant is for a clause
stating no number and this one states its own. Deliberately RD and not RA: the clause names no
attack it cannot be waived against.

**`HomensFeraRacialAbility.FORTALECIMENTO_FERAL`** — a flat `@Modifier(MOVEMENT)` of 1. "Seu
Movimento Base aumenta em +1UD" is the per-Ponto-de-Ação reading a `MOVEMENT` bonus lands
correctly, the same shape as `AtletismoCompetencyAbility.PASSO_LARGO` — not the one-shot-step shape
`SorteAdvantage.AS_NA_MANGA` over-grants under. The trait's "(dobro transformados)" half is
withheld; see §6.3.

**`GoblinsRacialAbility`** — two constants, and the most mechanically involved of the batch:

```java
// Poder dos Números — Vantagem em rolagens de Perícias while an ally is within Distância Curta,
// plus Vantagem em dano when at least one of those allies is itself a Goblin.
PODER_DOS_NUMEROS.resolveConditionalRollBonus(sceneContext, requestedAbility);
PODER_DOS_NUMEROS.resolveDamageBonus(skillType, sceneContext, attackTarget, actor);

// Autodesconfiança em Combate — Desvantagem em rolagens de Danos when no ally is close enough.
AUTODESCONFIANCA_EM_COMBATE.resolveDamageBonus(skillType, sceneContext, attackTarget, actor);
```

Both use `resolveConditionalRollBonus`/`resolveDamageBonus` rather than a flat `@Modifier`, because
a no-arg annotated method cannot see a `SceneContext`. Both widen `matchesSkillType` to every
Perícia — the clause says "rolagens de Perícias", not one named skill — the same technique
`AnoesRacialAbility.ABATEDORES_DE_GIGANTES` uses for its own "every Perícia de Ataque" scope.

**The two are exact complements, and that is what makes granting both safe.** One fires when an
ally is within `DISTANCIA_CURTA`, the other when none is — the rules text's "por estarem distantes
(Distância Média ou Superior)" is the same line drawn from the other side. So the Vantagem and the
Desvantagem on a dano roll can never both apply, and `AbstractSkillInteraction`'s first-non-empty
`resolveDamageBonus` lookup never has to break a tie. `GoblinsRacialAbilityTest` pins that across
six contexts.

The "aliado Goblin" check reads each nearby ally's own `Race` instance, so a `NascidoDoDragao`
whose parente is a Goblin does **not** count: it is a different Raça, and its text inherits
Características, not membership.

### 2.5 `Race#getCriticalEffectImmunities()`

```java
default Set<CriticalEffectType> getCriticalEffectImmunities() { return Set.of(); }
```

The player-facing counterpart to `MonsterTemplate#getCriticalEffectImmunities()`.
`AbstractCombatantSheet` reads it, so a race's immunities reach `CriticalEffect#applicableTo` with
no per-race wiring:

```java
CharacterSheet troll = CharacterSheet.of(trollCharacter, player);
troll.getCriticalEffectImmunities();
// → [ATORDOANTE, FERIDA_PROFUNDA, SANGRAMENTO]

CriticalEffect.applicableTo(troll, List.of(new Sangramento(ACERTO_CRITICO_MAIOR)));
// → []
```

`Troll`'s Anatomia Vegetal is the only race granting any, and is the first player-facing consumer
of the mechanism at all — before this, `AbstractCombatantSheet` returned `Set.of()` unconditionally
and only `MonsterSheet` ever overrode it.

**Only one of the three named effects has an implementation behind it** (`Sangramento`); Atordoante
and Ferida Profunda are named-only `CriticalEffectType` constants. That is precisely why the
immunity is keyed on the enum rather than on `Class<? extends CriticalEffect>` — the immunity is
real, exact data now, and is already being resisted correctly the day someone builds the effect.

**A player-*acquired* trait still has no path in.** This is one flat lookup on the race, not a scan
over held abilities, so `ProfissaoCompetencyAbility`'s still-unbuilt Resistência a Críticos remains
blocked.

### 2.6 Two multiplier traits seeded through `generateEmptyCharacter`

`NascidoDoDragao`'s Armadura Dracônica and `Guampo`'s Vigor de Epona both raise the Multiplicador de
PV by 1, and both are real:

```java
Character guampo = new Guampo().generateEmptyCharacter(List.of())/* … */.build();
guampo.getLifeMultiplier();                        // 5, i.e. DEFAULT_LIFE_MULTIPLIER + 1
hitPointsService.getMaxHitPoints(guampo);          // reflects it
```

This is the **same builder-seeding path `sizeCategory` already used** — `lifeMultiplier` is an
ordinary `Character` builder field, and `HitPointsServiceImpl#getLifeMultiplier` reads
`character.getLifeMultiplier()` as its base before summing any `LIFE_MULTIPLIER` modifier. It needs
no new hook, and is not a `@Modifier`: a multiplier is a `Character` field, not a modifier scan.

**Consequence worth knowing:** this path exists only through `generateEmptyCharacter`. A
`Character` assembled straight from `Character.builder()` — which `CharacterFixture` and most tests
do — bypasses it and gets the default multiplier, exactly as it already bypasses `sizeCategory`.

## 3. Behavior changes (no signature change)

### 3.1 `AbstractCombatantSheet#getCriticalEffectImmunities()` now consults the Race

It returned `Set.of()` unconditionally; it now returns `getCharacter().getRace()
.getCriticalEffectImmunities()`. Every race this library ships grants an empty set except `Troll`,
so **nothing changes unless a Troll is on the field** — or unless you author your own `Race`
overriding the new hook.

`MonsterSheet` still *overrides* wholesale rather than adding to it. A foe's anatomy is authored on
its `MonsterTemplate`, and its `Character`'s race is the catch-all `Monstruoso` (which grants
none), so there is nothing of the race's to lose.

### 3.2 `DamageServiceImpl` now sees racial abilities

`sumAcrossSources` scanned `character.getSkillCompetencyAbilities()`, the *acquired* list alone. It
now scans `SkillCompetencyAbility.allFor(character)`, which concatenates
`character.getRace().getRacialAbilities()` — matching what `MovementServiceImpl` and
`HitPointsServiceImpl#getHitPointsBonus` already did, and what CLAUDE.md's three-source-scan rule
already prescribed.

This affects both `DAMAGE_REDUCTION` and `ABSOLUTE_DAMAGE_REDUCTION`, and therefore
`getTotalDamageReduction`, `getTotalAbsoluteDamageReduction`, `calculateFinalDamage` and
`applyDamage`.

**No race in this library granted either before this release**, so no shipped race's numbers move.
It is listed here because a consumer who authored their own `Race` with an RD- or RA-granting
racial ability was silently getting 0 from it, and will now correctly get the grant — which looks
like a regression from the outside if you had compensated for it elsewhere.

`GuamposRacialAbility.VIGOR_DE_EPONA` is the first racial ability in the codebase to grant RD, and
`GuamposRacialAbilityTest#vigorDeEponaReachesTheDamageServiceThroughTheRace` exists specifically to
pin this scan rather than the constant.

## 4. New `TranslatableMessages` keys

`INVALID_ELEMENTAL_LINEAGE` — thrown by `NascidoDoDragao`'s constructor when the chosen
`ElementalType` is not one of Escamas Cromática's 8 Elementos Base. In practice this means
`ElementalType.TODOS`, which is a Magia-catalog convenience ("o Conjurador escolhe o elemento por
conjuração") with no row in the opposition table. A genuine system boundary — an authored choice
arriving from outside — validated the same way `SkillRoll` validates its dice.

## 5. Migration checklist

Short, because nothing was removed or renamed.

1. **Nothing to change** if you consume the shipped races and services. Recompile and go.
2. **If you author your own `Race`:** you may now override `getCriticalEffectImmunities()`. You do
   not have to — it defaults to empty.
3. **If you author your own `Race` with a racial ability granting RD or RA:** it now actually
   applies (§3.2). Re-check any figure you tuned around it not working.
4. **If you implement `DamageService` yourself** rather than using `DamageServiceImpl`: consider
   the same `allFor` change, or racial abilities stay invisible to your implementation.
5. **If you build `Character`s directly from `Character.builder()`** and want a Nascido do Dragão's
   or Guampo's PV multiplier, go through `race.generateEmptyCharacter(...)` instead — the same
   thing already true of `sizeCategory` (§2.6).
6. **Race count assertions**, if you have any: 21 → 29 concrete races, 2 → 6 `*RacialAbility`
   enums.

## 6. Known issues and deliberate gaps

### 6.1 Carried forward from 0.0.18

The same two pre-existing test failures, unrelated to this range and still unaddressed:
`SizeCategoryTest#shiftClampsAtThePlusFourCeiling` and
`CharacterSizeServiceTest#bonusIsClampedAtThePlusFourCeiling`. Both concern `SizeCategory#shift`
clamping to the full 15-value array while its javadoc claims a −4/+4 range. Verified still failing
with this range's changes stashed.

### 6.2 Resistência / Vulnerabilidade Elemental is the single biggest blocker in this release

Three separate races' headline Características die on the same missing mechanism, which makes it
the highest-value thing to build next:

- `NascidoDoDragao`'s **Escamas Cromática** — the element pair is exact data (§2.3); neither RE nor
  the vulnerability reaches a damage calculation.
- `Guampo`'s **Benção Divina** — RE to *every* element, so the missing mechanism is the whole of
  the clause.
- `Troll`'s **Anatomia Vegetal** vulnerabilities — Fogo for every Troll, plus Natural or Gelo by
  lineage.

`DamageType` has no elemental breakdown feeding RD/RA, and a *vulnerability* is a further stage
beyond that: nothing amplifies damage anywhere in this core. This is the same gap `Zumbi`'s "imune
a Profanos/Naturais, −3 vs Esmagamento" already cited.

Relatedly, `Troll`'s two sub-lineages (do Inverno / da Floresta) are deliberately **not** modelled
as a nested choice enum the way `Aviano.Subtipo` and `Ogro.Aptidao` are — those two exist because
the choice changes an Atributo map that is real today, whereas every clause distinguishing the two
Trolls is blocked on this mechanism. Add the enum with the mechanism, not ahead of it.

### 6.3 State-gated clauses are withheld rather than approximated

Where a clause's *amount* is exact but its *condition* is a state this core does not track, the
grant is withheld entirely rather than flattened — flattening would grant it permanently:

- **`Aviano`'s flight Movimento** (+2UD Rapinante / +1UD Correnuvens *while flying*) — no flight
  state. Contrast `HomensFeraRacialAbility.FORTALECIMENTO_FERAL`, whose +1UD half genuinely *is*
  unconditional and is therefore granted.
- **`HomemFera`'s Forma** — the form-scaled Atributos, Categoria de Tamanho, doubled Movimento and
  Armamentos Naturais all hang off one missing piece: a form state, plus "spend a resource to enter
  a timed state", plus (for the Duração) time-of-day and lunar phase.
- **`Indomito`'s Ferocidade de Lacerto** — the round condition *is* expressible today
  (`!sceneContext.isWithinFirstCombatRounds(3)`) and the Vantagem half would fit
  `resolveConditionalRollBonus` cleanly. It is withheld anyway because the clause is a state that
  can be *declined*: a temporary Autocontrole point prevents or ends it, nothing tracks whether an
  Indômito is currently ferocious, and `EgoPointsService#useEgoPointsForEffect` has no notion of
  spending a point to suppress an ongoing effect. Granting it on Rodada 4 would hand the bonus to
  an Indômito who paid to avoid it.

### 6.4 Two hooks `Race` still does not have

- **A racial Ego bonus or malus.** `Indomito.Tribo.IMPURO`'s −1 Autocontrole is the first trait to
  need one. `getFixedAttributeBonuses()` is typed to `AttributeDomain`; there is no
  `getFixedEgoBonuses()` counterpart, and `CharacterCreationServiceImpl` allocates Egos from the
  player's own points with no racial stage at all. The whole shape is missing, not a reader.
- **A race-granted `AttributeAbility`.** Pre-existing (`Orc`'s own Vigor de Epona and `MeioElfo`'s
  Aptidão Mágica Além-Élfica both cite it), and newly relevant for `Troll`'s "+2PV a cada Descanso
  Longo": `RestService#getRecoveredHitPoints` sums a bonus only via
  `AttributeAbility#resolveRestHitPointsBonus`, and `Race` can grant only
  `SkillCompetencyAbility`.

### 6.5 A finding this range surfaced but did not act on

`Orc`'s and `MeioElfo`'s javadocs both state that a "+1 Multiplicador de PV/PM" racial trait has
nowhere to plug in. **That is no longer accurate** — it is the same builder-seeding path §2.6 uses
for Armadura Dracônica and Vigor de Epona, and would be a one-line change on each race.

It was left alone deliberately: making those two real changes the stats of every existing Orc and
Meio-Elfo character, which is a rules decision rather than something to fold into an
add-races range. Both javadocs are consequently stale on this point until someone decides.

### 6.6 Unchanged gaps every new race inherits

Idiomas, Longevidade/idade, free Talentos, starting Perícia training/Especializações,
acquisition-slot grants, Visão no Escuro, Armas Naturais, and fractional Talento costs are all
still unmodelled, and each of the eight new races' javadoc names which of them it hits and why.
Two worth calling out because a new race made them concrete:

- **`Indomito`'s Monstros em Potencial** — counting Talentos Monstruosos is trivial, but
  `CreatureType` has only three constants (no MONSTRO, deliberately) and `getCreatureType()` takes
  no `Character`, so a creature type that changes with what its holder acquired cannot be
  expressed.
- **`Ogro`'s Bocarra / Devorar Inteiro** — needs a Corrente de Efeitos this core does not have, a
  containment relation ("a creature is inside another creature") nothing models, and a
  `TemporaryEffect` owned by the *swallower* rather than the victim.

### 6.7 One source-document defect carried as written

`HomemFera`'s prose says the race was blessed with "seis diferentes espíritos animais" and then
lists **seven**, each with its own paragraph, Senhor da Umbra, Atributo pair and Armamentos
Naturais row. All seven are transcribed; the count in the sentence is the defect.
`HomemFeraTest#theSourceDocumentListsSevenSpiritsDespiteSayingSix` pins it so nobody quietly drops
one. The prose also calls the first lineage *Licantropos* while both tables call it *Lobisomens*;
the constant keeps the prose's name, since that is where the lineage is described and Lobisomem is
one of its three forms.

Two further judgement calls are flagged on the classes themselves rather than resolved:
`HomemFera`'s `CreatureType.HUMANOIDE` (Monstro Interior says silver affects them "*como se
fossem* monstros", which only reads if they are not) and `Aviano`'s `CreatureType.MONSTRUOSO`
("apesar de serem considerados monstros", plus the Império's hostility "a raças não humanoides").

# Changelog — aventyrs-core 0.0.37

One fix, and it is load-bearing for anything that buys or crafts a weapon.

## A forged copy of an Arma is now an `Arma`

`ItemForgery#forge` (and `EquipmentCraftingService#forge`, which delegates to it) built every copy
through `AbstractItem.builder()`. A copy of a catalog Arma therefore came back as a bare
`AbstractItem`: `instanceof Weapon` was **false**, so the copy

- could not be drawn — `Character#drawWeapon` takes a `Weapon`,
- could not be an attack's `AttackSource`, so no Perícia de Ataque could name it, and
- could not be handed to `DamageBaseService#getDamageBase(Character, Weapon)` at all.

In other words a bought or crafted sword could not be swung; only Armas Naturais and Ataque
Desarmado (which come from the catalog enums directly, never through a forge) worked.

`AbstractItem.builderFromTemplate` now returns an `AbstractWeapon` builder when the template it is
handed is itself a `Weapon`, carrying that template's `damageBase`, `skillType` and `range`. Both
forge paths and `AbstractItem.fromTemplate` are fixed by that one change.

**No migration:** a stored item is reconstructed from its `templateName`, so copies bought before
this version come back as real weapons on the next load.

**Known gap:** `Weapon#getCriticalEffect()` and `#getLesserCriticalMargin()` are interface defaults
with no `AbstractWeapon` field, so a forged copy reports the defaults rather than its catalog
entry's authored Efeito Crítico. Nothing reads those two yet; they need fields on `AbstractWeapon`
first.

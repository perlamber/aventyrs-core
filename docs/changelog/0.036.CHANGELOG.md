# Changelog — aventyrs-core 0.0.36

Written for projects that consume this library. One theme: **an attack starts from the weapon.**
A Perícia de Ataque roll is no longer something a caller picks alongside a free choice of
Especialização — the `AttackSource` decides both.

## 1. `AttackSpecializations` (new, `org.aventyrs.core.skill`)

- `requiredFor(AttackSource, Character)` — the Especialização an attack source is rolled with:
  - Arma Natural (via `Character#treatsAsNaturalWeapon`, including `NaturalWeapon.ATAQUE_DESARMADO`)
    swung corpo-a-corpo → `PRIMAL`; a ranged Arma Natural → empty.
  - `ItemCategory.THROWABLE` → `TECNICAS_DE_ARREMESSO`.
  - Any other weapon → the Especialização of its own Perícia whose `weightClasses` contains the
    weapon's **base** `getWeightClass()` (Infantaria Leve/Pesada, Artilharia Leve/Pesada).
  - `Spell` → `CONJURADOR_DE_LINHA_DE_TRAS` (ranged) / `ARCANISTA_DE_LINHA_DE_FRENTE` (melee).
  - `ARMAS_TECNOLOGICAS` is never answered — no Item carries a technological marker yet.
- `heldFor(AttackSource, Character)` — the same, kept only when the character holds it
  (`Character#getSpecializations(SkillType)`, so Talento-granted ones count). Pass it straight to
  `SkillRoll` as the `requestedAbility`: present → expert roll, empty → plain roll.

```java
Optional<SkillSpecialization> specialization = AttackSpecializations.heldFor(weapon, character);
SkillRoll roll = new SkillRoll(dice, specialization.orElse(null));
DeliveredAttack.builder().attackSkill(weapon.getSkillType()).attackSource(weapon).attackRoll(roll)...
```

## 2. Behaviour change: a mismatched Especialização de Ataque is refused

`AbstractSkillInteraction` now throws `IllegalOperationException(REQUIRED_SKILL_TRAIT_NOT_HELD)` when
a roll requests an Especialização of a Perícia de Ataque **and** names an `attackSource` that
Especialização doesn't fit — even if the character holds it. Rolls with no `attackSource` keep the
old held-only check.

**Migration:** if you built `SkillRoll`s with a player-chosen attack Especialização, derive it with
`AttackSpecializations.heldFor` instead.

# Changelog — aventyrs-core 0.0.41

Two additions, both about Acertos Críticos: **the Margem Crítica Menor now decides whether a roll
crits**, and **a critical hit now changes the dano roll**.

## Margem Crítica Menor — a 3d6 total, read off the weapon

`Weapon#getLesserCriticalMargin()` has carried each Arma's authored number since the catalogs were
written (`Sangramento (17)`, a Besta de Mão's `(16)`) and was read by nothing. It is now the rule.

- **`SkillRoll#getCriticalResult(int criticalMarginIncrease, int lesserCriticalMargin)`** — new
  overload, and the one that decides an Acerto Crítico Menor: the roll crits when its **total**
  reaches `lesserCriticalMargin - criticalMarginIncrease`, floored so widening can never overturn a
  Falha Crítica. Lower is wider.
  - `getCriticalResult(int)` now delegates with `Weapon.DEFAULT_LESSER_CRITICAL_MARGIN` (17);
    `getCriticalResult()` is unchanged in meaning.
  - **Behaviour change:** the old rule was "two dice showing 6, lowered by the margin", an
    approximation invented here. Two 6s alongside a low third die (total 13) is no longer a
    critical; a 5+6+6 (17) is. Callers asserting on dice combinations need rewriting — every
    affected test in this repo was.
- **`AbstractSkillInteraction`** passes the attack's own weapon margin, and sums a fifth widening
  source alongside the Habilidade/Excelência/Vantagem/Talento passes it already ran: the wielded
  weapon's fitted enhancements.
- **`Item#resolveEnhancementCriticalMarginIncrease(Weapon, Character)`**, backed by new
  `Improvement#resolveCriticalMarginIncrease` / `Masterpiece#resolveCriticalMarginIncrease` hooks —
  host-scoped exactly like `resolveEnhancementDamageBaseIncrease`, so a Decisiva adaga sharpens
  nothing while an espada is being swung.
  - Live: `OffensiveMasterpiece#DECISIVA` and `#MITRAL` (+1 each, both Características Adicionais,
    so ungated).
  - Still TODO: `BANHADA_EM_PRATA` (needs the target's Monstro classification) and
    `BANHADA_EM_OURO` (needs which Defesa the attack was rolled against). Decisiva's *Favor* is a
    Margem Crítica **Maior**, which this ruleset models nowhere.

## Dano Crítico — a critical hit's own contribution to the dano roll

- **`org.aventyrs.core.character.CriticalDamage(int extraDice, int flatBonus)`** — further d6 for
  the caller to roll plus a flat add, with `NONE`, `ofDice`, `ofFlat`, `plus` and `isNone`.
  A third stage: not a `DamageBase` scale-up (it is conditional on the attack roll) and not a
  `DamageBonus` (which has no room for a die). `extraDice` is **not** capped by `DamageBase.MAX_DICE`.
- **`InteractionResult#criticalDamage`** — populated only on a critical success with a Perícia de
  Ataque, `null` otherwise. **Never folded into `damageBonus`**, so a caller adds each exactly
  once: roll `extraDice` d6, add `flatBonus`, add the `DamageBonus`.
- **The baseline** — Vantagem em Danos, `Skill#ADVANTAGE_BONUS` and no die — is granted by
  `AbstractSkillInteraction#sumCriticalDamage` itself, held by nobody, the same way the half-Força
  term and an Investida's +2 are.
- **New hooks**
  - `Feat#resolveCriticalDamage(SkillType, SceneContext, Character, AttackSource, CriticalResult, SkillRoll)`
  - `Feat#replacesBaselineCriticalAdvantage(SkillType, AttackSource, Character)` — one holder
    saying so drops the +2 for that attack, however many other sources then add to it.
  - `Improvement#resolveCriticalDamage(Weapon, Character)` /
    `Masterpiece#resolveCriticalDamage(Weapon, Character)`, aggregated by
    `Item#resolveEnhancementCriticalDamage`, host-scoped like the margin hook.
- **Live grants**
  - `ArtilhariaFeat#MIRA_MORTAL` — +1d6, so a 1d6 weapon rolls 2d6 (+2) on such a crit.
  - `AssassinoFeat#VIOLENCIA_DESCOMUNAL` — replaces the +2 with +1d6.
  - `OffensiveImprovement#CRUEL` — +3 (its Favor "muda para" its own +2 rather than stacking, and
    an Aprimoramento has no Requisitos to gate it).
  - `OffensiveMasterpiece#MITRAL` — +3, gated on its Requisitos, being a Favor.
  - Not expressible: a weapon **Favor**'s "Danos Críticos +1d6" — `ItemFavor` carries
    `ModifierType`-typed `ItemBonus`es, which cannot express a die.

## "This roll activated a Talento"

- **`SkillRoll#getActivatedFeats()` / `activated(Feat)`**, set through the new 6-arg constructor
  (`…, Manoeuvre, Set<Feat>`); every shorter constructor passes none, and the getter never returns
  `null`.
- Roll metadata on the same terms as `manoeuvre`: **which Talentos the roller spent**, as opposed
  to merely held. This is the scoping several TODOs named as missing ("an attack made by activating
  another Talento"), and it is what makes Mira Mortal's "usando o talento ‘Mira Impecável’" real.
  `ArtilhariaFeat#TIRO_LONGO` and `#ABATER_A_CACA` could now use it too; neither was wired here.

## Migration

- A caller that rolls damage should read `InteractionResult#getCriticalDamage()` and, when
  non-`null`, roll that many extra d6 and add the flat bonus.
- A caller that offers a per-roll Talento opt-in (a reroll bought with +1PA, say) should name it on
  the `SkillRoll`'s `activatedFeats`.
- Tests asserting critical outcomes must state dice by **total**, not by matching faces.

# Changelog — aventyrs-core 0.0.40

One addition: **Campanhas and their Sessões**, and the rule that a character does not progress
while a Sessão is being played.

## `org.aventyrs.core.campaign`

- `SessionStatus` — `CREATED → ONGOING → ENDED`, one way only (`canTransitionTo`).
- `Session` — `id`, `number` (1..n), `status`. Created through `Campaign#createSession()`;
  `Session.of(id, number, status)` rebuilds a stored one.
- `Campaign` — `id`, `name`, ordered `sessions`, `participantSheetIds`.
  - `create(name)` / `of(id, name, sessions, participantSheetIds)` (the latter refuses gapped
    numbering or more than one open Sessão).
  - `createSession()` — next number, `CREATED`; refused with `SESSION_ALREADY_OPEN` while
    another Sessão is not yet `ENDED`.
  - `startSession(number)` / `endSession(number)` — `SESSION_NOT_FOUND`,
    `SESSION_ALREADY_ONGOING`, `INVALID_SESSION_TRANSITION`.
  - `getOngoingSession()`, `getSession(number)`, `findSession(number)`.
  - `addParticipant` / `removeParticipant` / `isParticipant` (by `CharacterSheet` id; allowed at
    any time).
  - **`isProgressionLocked()` / `requireProgressionAllowed()`** — throws
    `PROGRESSION_LOCKED_DURING_SESSION` while a Sessão is `ONGOING`.

**The lock is not enforced by any progression service.** Call `requireProgressionAllowed()`
before `FeatService#grantFeat`, `SkillGraduationService#upgradeGraduation`,
`CharacterAttributeService#upgradeBase`, `AttributeAbilityService#grantAttributeAbility`/
`grantCompetencyAbilityChoice`/`grantSpecializationChoice`, `TitleAcquisitionService#grantTitle`
and `TitleAbilityService#grantTitleAbility`. No existing signature changed.

## New `TranslatableMessages` keys

`PROGRESSION_LOCKED_DURING_SESSION`, `INVALID_SESSION_TRANSITION`, `SESSION_ALREADY_ONGOING`,
`SESSION_ALREADY_OPEN`, `SESSION_NOT_FOUND`.

## Session-end acquisitions — Despertar Antecipado

`DestinoFeat#DESPERTAR_ANTECIPADO` is real: the player picks the Título when taking the
Talento at creation, and it is awakened as Título Primário when the session ends.

- **`CharacterSheet#applySessionEndAcquisitions()`** — call it on each participant's sheet
  after `Campaign#endSession`. It grants every `sheet.PendingAcquisition` a held Talento still
  owes and returns them (empty when nothing was owed). Calling it twice is harmless. Nothing is
  stored on the sheet: owed acquisitions come from the Talentos.
- `Feat#resolveSessionEndAcquisitions(Character)` — new hook, empty by default.
- `feat.DespertarAntecipadoFeat` — the acquired form. `of(holder, title)` /
  `optionsFor(holder)`; the constant's `resolveRequiredChoices` now declares a
  `FeatChoice<AventyrTitle>`, so the **bare constant is refused** (`FEAT_REQUIRES_CHOICE`).
- `Feat#isAcquirableOnlyAtCreation()` — "Apenas personagens recém-criados". True for
  `DESPERTAR_ANTECIPADO`: `FeatService#grantFeat` refuses it, `FeatCatalog#availableFor` /
  `FeatService#getAvailableFeats` leave it out, and only
  `CharacterCreationService#grantStartingFeats` grants it.
- `title.TitleCatalog` — `all()` returns one fresh instance of every Título family (Santo
  only). `isSameFamily(a, b)` compares two titles by family.
- `title.TitleAwakening(title, slot)` — a `PendingAcquisition` granting through
  `TitleAcquisitionService#grantTitle`, so a Talento prohibition applies at awakening too.
- `TitleAcquisitionService#isPermitted(character, title)` — the non-throwing check.

### New `TranslatableMessages` keys

`FEAT_ONLY_AT_CREATION`, `DESPERTAR_ANTECIPADO_CHOICE_NOT_ELIGIBLE`.

### Consumer impact

`TitleAcquisitionService` gained an abstract method, so any other implementation of it must add
`isPermitted`. A persisted Despertar Antecipado must now store its chosen Título, because
the bare constant name no longer describes the Talento.
